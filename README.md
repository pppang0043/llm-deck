# LLM Deck

Waveshare ESP32-S3-Touch-LCD-2 보드로 만든 책상용 기기.
LLM 구독 한도 사용률을 보여주고, 카메라로 사진·동영상을 찍어 PC 에 저장하며, PC 의 마이크 입력으로도 쓴다.

- `firmware/` — 보드에 올라가는 프로그램 (PlatformIO + Arduino)
- `companion/` — PC 에서 실행하는 도우미 (Python, Mac·Windows). 사용량을 모아 기기로 보내고, 기기가 보내는 사진·동영상·소리를 받는다

## 기기 화면

켜면 홈 화면이 나온다. 어느 화면에서든 **오른쪽으로 밀면 홈**으로 돌아온다.

| 아이콘 | 하는 일 |
|---|---|
| 사용량 | Claude Code / Codex 한도 사용률 (5시간·주간). 서비스가 여럿이면 위아래로 넘긴다. 구간을 누르면 최근 24시간 그래프 (10분마다 기록, 다시 켜도 남음). 그래프 오른쪽 위 **7일** 버튼을 누르면 최근 7일 동안 날마다 오른 % 를 막대로 보이고, 가장 많이 쓴 날(요일)과 시간대(예: 14~16시)를 알려 준다 (1시간 단위로 7일치 기록, 초기화로 떨어진 것은 빼지 않는다). 최근 속도(5시간은 1시간, 주간은 6시간 동안 오른 만큼)로 초기화 전에 한도가 찰 것 같으면 구간 아래에 "16:40 소진" 처럼 예상 시각이 노랗게 나오고, 소진까지 5시간 구간은 1시간, 주간은 12시간 안으로 남으면 "이 속도면 40분 뒤 소진" 알림을 80% 알림과 같은 소리로 구간마다 한 번 띄운다 (설정 > 알림 및 사운드 > 한도 알림을 따른다). 한도 페이지 다음은 **API Cost**: 이 PC 의 Claude Code·Codex 대화 기록 토큰 수에 API 단가를 곱한 "API 로 썼다면 든 비용" (오늘·이번 달, 키 필요 없음, 5분마다 다시 셈, `companion/collectors/api_cost.py`). `config.toml` 에 Admin 키를 넣으면 실제 API 청구액 페이지 **API Billing** 이 나온다 (Anthropic·OpenAI 를 한 화면에 표로: 이번 달, 오늘, 한도 남음, 크레딧). 같은 곳에 `monthly_limit`(월 한도), `credit`·`credit_date`(크레딧 잔액과 본 날짜)를 적으면 "한도 남음", "크레딧 남음" 줄이 붙는다 (두 회사 모두 잔액 API 가 없어 적은 값에서 그 뒤 쓴 금액을 뺀다. OpenAI 월 한도는 비워 두면 조직 설정에서 읽는다). 키 만료일은 `expires` 에 적으면 7일 전부터 알린다. 맨 마지막 페이지는 PC 상태: 사용 중인 PC 의 CPU, 메모리, 디스크 여유, 네트워크 속도, 배터리 (이 페이지를 보는 동안만 PC 가 3초마다 보내 준다). 아래(가로 화면은 오른쪽) 버튼은 **받아쓰기**: 한 번 누르고 PC 마이크에 말한 뒤 다시 누르면, 받아 적은 글이 PC 에서 지금 커서가 있는 곳에 입력된다 (Claude 에 묻지 않고, Enter 는 누르지 않는다. Mac 은 손쉬운 사용에서 LLM Deck 허용 필요). 받아쓰기·질문 모두 한 번에 최대 60초 녹음하고, 넘으면 저절로 끝낸다 |
| 카메라 | 미리보기. 흰 버튼 = 사진(1600x1200), 빨간 버튼 = 녹화(640x480, PC 와 SD 카드에 MOV 로 저장. 카드가 있으면 PC 없이도 녹화된다). 아래로 밀면 닫힌다. 녹화 중이 아니면 2분 동안 안 만질 때 스스로 닫는다 (센서가 뜨거워지지 않게, 닫으면 센서 전원도 끈다). 오른쪽 위 버튼은 **갤러리**: SD 카드의 사진·동영상을 작은 그림 격자로 최근 것부터 보여 주고(위 가운데 버튼으로 전체/사진/동영상), 누르면 크게 본다. 크게 볼 때 왼쪽으로 밀면 더 오래된 것, 오른쪽으로 밀면 더 최근 것, 아래로 밀면 격자로. 동영상은 화면을 누르면 재생·멈춤. 오른쪽 아래 휴지통을 3초 안에 두 번 누르면 카드에서 지우고, 왼쪽 아래 버튼은 사진을 PC 로 다시 보낸다. 보는 동안 카메라는 꺼 둔다 (`--camera gallery` 로도 연다) PC 로 보내는 동안 위에 진행률이 나오고, 블루투스처럼 오래 걸린 전송은 끝나면 알림이 뜬다 |
| 질문 | 버튼을 한 번 누르고 **PC 마이크**에 말한 뒤 다시 누르면, PC 도우미가 받아 적어(PC 안에서, faster-whisper) Claude Code CLI 에 묻고 답을 글로 보여 준다. 구독 계정으로 동작한다 (CLI 는 `claude-test` 를 먼저 찾고 없으면 `claude`). 앞 대화를 이어서 묻는다. "새 대화" 로 끊는다. 두 번째 질문부터 다시 누른 뒤 2~3초. 스피커 버튼으로 음소거를 풀면 답을 PC 스피커로 읽어 준다: 앞 1~2문장(요약)만 읽고, 질문에 "길게", "자세히", "전부" 같은 말이 있으면 전체를 읽는다. CLI 는 백그라운드에 띄워 두고 30분 동안 질문이 없으면 끈다. PC 가 없거나 PC 에 마이크가 없으면 버튼이 꺼진다 (`companion/assistant.py`) |
| 단축키 | 왼쪽 끝 칸에서 "프로그램" / "키워드" 를 고른다. 프로그램: 사용 중인 PC 에서 엑셀, 파워포인트, ORCA, 파워쉘, 파워쉘(관리자)을 연다 (관리자는 PC 에서 "예" 를 눌러야 열린다. 파워쉘은 Windows 만). 키워드: PC 에서 지금 커서가 있는 곳에 "커밋해줘", "배포해줘", "푸쉬해줘", "에러 확인", "/orchestration", "/clear", "/compact" 를 입력하고 Enter 를 누른다. 버튼과 글은 `config.toml` 의 `[keywords]` 에서 7개까지 바꿀 수 있다 (펌웨어를 다시 올리지 않아도 PC 도우미를 다시 켜면 기기에 반영되고, 기기는 받은 목록을 기억한다. 글은 PC 에만 두고 기기는 버튼 이름만 받는다) (Windows 는 한/영 상태와 상관없이 한글이 들어가고, 관리자 권한 창에는 안 들어간다. Mac 은 처음 한 번 손쉬운 사용에서 LLM Deck 을 허용해야 한다). PC 도우미가 정해 둔 것만 연다·입력한다 (`companion/launcher.py`, `companion/typer.py`). 결과는 화면에 알림으로 나온다 |
| ORCA | PC 의 ORCA 에 열린 세션과 작업 상태(작업 중, 입력 기다림, 권한 요청 등). PC 도우미가 10초마다 읽는다. 세션을 누르면 PC 에서 그 세션을 앞으로 띄우고 받아쓰기를 시작하고, 다시 누르면 받아 적은 글을 그 세션에 넣는다 (Enter 없이). "슬래시 커밋" 처럼 말하면 "/commit" 으로 바꾼다. 세션을 길게 누르면 빠른 답: 권한 요청은 "허용"(1) / "거부"(Esc), 입력 기다림·완료는 "계속" (+ Enter). PC 도우미가 정해 둔 답만, 보내기 직전에 상태를 다시 확인하고 보낸다. 세션에 새 권한 요청이 뜨거나 작업이 끝나면 어느 화면에서나 알림과 소리가 난다 (기기를 켠 직후 처음 받은 목록은 알리지 않고, 같은 세션의 같은 알림은 1분에 한 번). ORCA 가 꺼져 있으면 그렇다고 나온다 (`companion/orca.py`) |
| 설정 | 아래 표 |

상태줄: 왼쪽은 지금 연결된 방식, 오른쪽은 날짜·시각, 배터리(충전 중이면 번개, 다 차면 100%), 화면 돌리기 버튼.

## PC 와 연결하기

기기는 여러 방식을 동시에 켜 두고, 살아 있는 것 중 **USB > Wi-Fi > 블루투스 > 클라우드** 순으로 하나를 쓴다.
사진·동영상·알림음·마이크 소리는 그 PC 로 간다. 두 PC 가 동시에 붙어도 우선순위가 높은 쪽이 유지된다.

| 방식 | 준비할 것 | 사진 | 동영상 |
|---|---|---|---|
| USB | 케이블 | 0.3초 | 초당 약 16장 |
| 블루투스 | PC 블루투스만 켠다. 운영체제에서 "페어링" 하지 않는다. PC 3대까지 동시에 | 100KB 에 약 4~5초 | 안 됨 (USB 를 연결하라고 안내) |
| Wi-Fi | 기기와 PC 가 같은 공유기. 기기에 Wi-Fi 등록 (아래) | 1초 안팎 | 초당 약 14장 |
| 클라우드 | 없음. PC 없이 Wi-Fi 만 있으면 기기가 공유된 사용량을 직접 읽는다 | - | - |

블루투스로 붙어 있다가 USB 를 꽂으면 도우미가 30초 안에 USB 로 바꾼다. 블루투스로 붙어 있는 동안 도우미와 기기는 5분마다 Wi-Fi 를 다시 찾아, 되면 Wi-Fi 로 바꾼다.

블루투스는 Wi-Fi 를 쓸 수 없는 곳(회사 무선 보안(WIPS)이 개인 기기의 Wi-Fi 접속을 막는 곳 등)을 위한 마지막 방법이다. ESP32-S3 는 클래식 블루투스가 없어 BLE(저전력 블루투스)로만 붙고, 운영체제 블루투스 설정에 기기로 등록(페어링)하지 않아도 도우미가 직접 찾아 연결한다. BLE 는 암호화 없이 붙으므로 Wi-Fi 와 같은 인증 키(USB 로 한 번 연결할 때 받는다)로 서로 확인하고 명령·알림마다 서명한다. 키 없는 PC 는 명령이 모두 거절되고 "사용 중" PC 가 되지 못하며 20초 뒤 끊긴다. 가짜 기기가 PC 에 입력·앱 실행을 시킬 수도 없다. 다만 내용을 숨기지는 않아(서명만, 암호화 없음) 근처에서 사용량 같은 내용을 엿볼 수는 있다. 그래서 블루투스만 쓸 PC 도 처음 한 번은 USB 로 연결해야 한다.

## PC 도우미

### Mac

```sh
cd companion
sh macos/install.sh            # 로그인할 때 자동 실행 (블루투스 권한을 받으려고 LLM Deck.app 으로 감싼다. 메뉴 막대 아이콘에서 미러링 창을 연다)
sh macos/install.sh uninstall  # 제거
```

기록: `~/.llm-deck/companion.log`. 자동 실행 중인 도우미를 잠시 끄기:
`launchctl bootout gui/$(id -u)/com.llmdeck.companion` (다시 켜기: `sh macos/install.sh`)

### Windows

`dist/llm-deck-companion-windows.zip` 을 풀고 맨 위의 `install.cmd` 를 더블클릭한다 (도우미 코드는 `app` 폴더). 자세한 내용은 압축 안의 `README.txt`.
PC 에 깔린 64비트 Python 3.11~3.14 가 있어야 한다 (회사 보안이 막는 uv 는 쓰지 않는다). 설치는 그 Python 으로 `app\.venv` 를 만들어 `requirements.txt`(uv.lock 과 같은 버전·파일 지문)대로 pip 로 깔고, 방화벽 허용(같은 공유기 안에서만), Claude Code 상태줄 연결, 자동 실행 등록을 한다.
트레이 아이콘·미러링 창은 `windows/app.pyw` 를 `pythonw.exe` 로 돌린다 (설치 때 exe 를 만들지 않아 보안 프로그램에 걸리지 않는다).
기록: `C:\Users\<이름>\.llm-deck\companion.log`.

압축 파일 다시 만들기 (gist 주소만 넣고 토큰은 넣지 않는다. `requirements.txt` 도 uv.lock 으로 새로 만든다): 이 저장소에서 `companion/.venv/bin/python companion/windows/make_zip.py`.

| 동영상 (MOV, Motion JPEG 원본 그대로) | `~/Movies/LLM Deck` | `%USERPROFILE%\Videos\LLM Deck` |
| SD 카드 (FAT32) | 사진 `/photos`, 동영상 `/videos` | 같음 |

폴더에 쓸 수 없으면(Windows 의 "제어된 폴더 액세스" 등) `~/.llm-deck/photos`, `~/.llm-deck/videos` 에 저장한다.
`config.toml` 의 `[photos] dir`, `[videos] dir` 로 바꿀 수 있다. 기기에 microSD 카드를 넣으면 사진은 카드의 `/photos` 에도 저장된다.

### 명령

도우미는 PC 에 하나만 돈다. 자동 실행 중이면 직접 실행하기 전에 끈다 (두 번째로 켜면 안내만 하고 끝난다).

```sh
uv run main.py                     # 되는 방식으로 자동 연결 (USB -> Wi-Fi -> 블루투스)
uv run main.py --link ble          # 방식 고르기: usb / ble / wifi
uv run main.py --install-statusline  # Claude Code 한도 사용률 읽기 (PC 마다 한 번)
uv run main.py --add-wifi          # 기기에 Wi-Fi 추가 (USB 로 연결한 상태, 최대 5개, 2.4GHz)
uv run main.py --setup-sync        # 여러 PC 가 사용률을 공유할 비공개 gist 만들기 (처음 한 번)
uv run main.py --test-sound        # 알림음 들어 보기
uv run main.py --bt-check          # 기기가 블루투스 스피커에 붙을 수 있는지 시험 (USB)
uv run main.py --assistant-check   # 질문에 쓸 Claude CLI 찾기 (claude-test 먼저, 없으면 claude)
uv run main.py --camera shoot      # 사진 찍기 (open / record / close / dump)
uv run main.py --test-video 5      # 5초 녹화
uv run main.py --saver             # 화면 보호기를 지금 띄워 보기 (만지면 사라짐)
uv run main.py --rotate            # 화면 90도 돌리기 (돌리기 버튼과 같다)
uv run main.py --sd-clear          # 기기 SD 카드의 사진 모두 지우기 (USB)
uv run main.py --screenshot        # 기기 화면을 찍어 사진 폴더에 저장 (--view home|usage|info|settings 와 함께)
uv run main.py --mirror            # 미러링 창: 기기 화면을 보고 클릭·끌기·휠·화살표로 조작 (도우미가 켜져 있고 USB·Wi-Fi 연결일 때). 설치한 도우미 앱(Mac 은 메뉴 막대의 LLM Deck, Windows 는 트레이의 LLM Deck)의 창으로 열고, 앱이 없을 때(터미널에서 직접 띄운 도우미 등)만 브라우저로 연다. 기기가 USB·Wi-Fi 로 새로 연결되면 도우미 앱 창이 저절로 열린다 (끄려면 [mirror] auto_open = false). 항상 위는 창 오른쪽 메뉴와 메뉴 막대·트레이 메뉴에서 고른다. 미러링이 시작되면 기기 화면에는 구독 한도 표가 나오고, 기기를 한 번 만지면 원래 화면으로 돌아와 그 뒤로는 기기와 창을 따로 쓴다 (다음 연결 때까지 한도 표로 돌아가지 않음)
uv run main.py --links ble=off     # 연결 방식 켜고 끄기 (USB 로만, USB 를 꺼 둬도 받는다)
uv run main.py --camera-mount 0m   # 카메라 방향 (0~3, 좌우 반전이면 m)
uv run main.py --battery 4.12      # 멀티미터로 잰 배터리 전압으로 보정 (0 이면 보정 지움)
```

## 여러 PC 에서 사용률 함께 보기

Claude Code / Codex 가 없는 PC 에 연결해도 최신 값을 보려면, 값을 비공개 GitHub gist 로 공유한다.
값을 올리는 PC 는 `gh auth login -s gist` 로 로그인하거나 `config.toml` 의 `[sync] github_token` 에 gist 권한 토큰을 적는다.
받기만 하는 PC 는 `gist_id` 만 있으면 된다. 기기에 연결된 PC 에 값이 있으면 그 값을 먼저 쓰고, 없을 때만 공유된 값을 쓴다.
기기는 공유 주소를 기억해, PC 가 없어도 Wi-Fi 로 직접 읽는다 (상태줄 "클라우드").

상태줄 파일과 Codex 세션 기록은 그 PC 에서 마지막으로 응답을 받은 순간의 값이라, 다른 기기(웹, 폰, 다른 PC)에서 쓴 양이 늦게 반영된다.
그래서 도우미는 2분마다 서버에도 직접 묻는다 (Claude Code 의 `/usage`, Codex 의 `/status` 가 쓰는 곳, `companion/collectors/server.py`). 계정 전체 기준이라 어느 기기에서 썼든 바로 맞고, 이 값도 gist 로 올라간다.
그 PC 의 Claude Code / Codex 로그인을 그대로 쓰며, 로그인이 만료됐거나 서버가 답하지 않으면 묻지 않고 기존 값을 쓴다 (로그인은 Claude Code / Codex 를 쓸 때 스스로 새로 받는다). 끄려면 `config.toml` 의 `[claude_code]`, `[codex]` 에 `server = false`.

## 펌웨어 올리기

```sh
cd firmware
~/.local/bin/pio run -t upload
```

도우미가 USB 포트를 잡고 있으면 올라가지 않는다. 먼저 끈다.
다른 ESP32 기기(M5 StickS3 등)가 같이 꽂혀 있으면 자동으로 고른 포트가 틀릴 수 있으니 `--upload-port` 로 이 보드의 포트를 지정한다.

무선(Wi-Fi) 업로드: `secrets.h` 의 `OTA_PASSWORD` 를 정한 펌웨어를 USB 로 한 번 올린 뒤부터, 같은 공유기에서

```sh
LLMDECK_OTA_PASSWORD=$(cat ~/.llm-deck/ota_password) ~/.local/bin/pio run -e ota -t upload   # 주소가 다르면 --upload-port <IP>
```
인터넷 회사 DNS 가 `llm-deck.local` 에 바깥 주소를 대답하기도 해서, 업로드 전에 집 안 주소만 골라 쓴다 (`firmware/scripts/ota_port.py`).
`firmware/include/secrets.h` 에 기본 Wi-Fi 이름·비밀번호를 적는다 (git 에 올라가지 않는다).

## 블루투스 스피커 (ATOM Lite 모듈)

이 보드의 칩(ESP32-S3)은 블루투스 스피커가 쓰는 클래식 블루투스(A2DP)가 없다.
그래서 원조 ESP32 칩이 든 M5Stack ATOM Lite 를 붙여, 보드는 "이 소리 내 줘" 만 보내고 모듈이 스피커에 연결해 소리를 낸다 (`speaker/`).

배선: 모듈의 Grove 단자 4가닥을 보드 헤더에 꽂는다. 터치 센서와 같은 I2C 선을 나눠 쓴다 (주소 0x2A).

| ATOM Lite (Grove) | 보드 헤더 |
|---|---|
| GND | G (2번) |
| 5V | 아래 "전원" 참고 |
| G26 (SDA) | GPIO48 (6번) |
| G32 (SCL) | GPIO47 (5번) |

전원: ATOM Lite 는 5V(최대 500mA)를 받는다. 보드의 3.3V 핀에 물리지 않는다 (보드 전원이 모자라 재부팅될 수 있다).
보드의 5V 핀(15번)은 USB 가 꽂혀 있을 때만 전기가 나올 수 있으니, 배터리로 쓸 때는 VBAT(14번)에 5V 승압 모듈을 달아 연결한다.
VBAT 를 승압 없이 바로 연결해도 되는지는 아직 재 보지 않았다. 모듈을 따로 USB 로 켤 때는 GND 만 잇고 5V 끼리는 잇지 않는다.

모듈 펌웨어 올리기 (모듈만 USB 로 꽂고):

```sh
cd speaker
~/.local/bin/pio run -t upload --upload-port <모듈 포트>
```

쓰는 법: 설정 > 스피커 > "찾기" (스피커는 페어링 모드로) > 목록에서 누르기. 연결되면 시험 소리가 난다.
그 뒤로 마이크 알림음과 한도 알림음은 스피커로 나간다 (모듈이 없거나 "스피커로 알림음" 을 끄면 전처럼 PC 스피커로).
모듈 LED: 꺼짐 = 쉬는 중, 파랑 = 연결 중, 노랑 = 찾는 중, 초록 = 연결됨.

전기: 기본은 소리를 낼 때만 블루투스를 켜고 30초 뒤 끈다 (처음 소리가 몇 초 늦다). "항상 연결" 을 켜면 바로 나지만 전기를 더 쓴다.
I2C 선은 느려서 소리 데이터를 보내지 않고, 알림음은 모듈이 직접 만든다.
마이크 알림음은 6초 안에 스피커에 못 붙으면 버린다 (늦게 나면 켬/끔이 헷갈리므로). 한도 알림음은 25초까지 기다린다.

모듈이 오면 시험할 것: 스피커 찾기와 연결, 연달아 알림, 1분·10분·30분 조용히 둔 뒤 첫 알림,
모듈이나 스피커를 다시 켠 뒤 다시 붙는지, 휴대폰이 스피커에 먼저 붙어 있을 때, PC 3대 연결과 터치 중에도 명령이 빠지지 않는지.

## 알아둘 것

- 보드에는 마이크가 없다. INMP441 I2S 마이크를 달면(SCK 18, WS 43, SD 44) 마이크 소리가 PC 로 간다. PC 에서 마이크로 쓰려면 Mac 은 BlackHole, Windows 는 VB-CABLE 이 필요하다
- 블루투스는 PC 3대까지 동시에 붙는다. 인증한 PC 중 "사용 중" 인 PC 하나만 마이크 소리·사진·알림음을 받고, 화면의 사용량도 그 PC 것을 쓴다. 나머지는 기다리며, 사용 중인 PC 가 끊기면 이어받는다. 설정에서 고른 PC 는 기억해 두었다가 다시 붙으면 먼저 쓴다
- 블루투스 신호가 약하면(-70dBm 아래) PC 가 기기를 찾아도 연결이 자주 실패한다. 기기를 PC 가까이 둔다
- 기기 내부 RAM 이 빠듯하다 (켠 뒤 남는 양 약 70KB). 암호화 통신(HTTPS)과 블루투스 버퍼, 클라우드 작업 스택은 큰 메모리(PSRAM)에 둔다. 카메라용 20KB 는 부팅 때 미리 잡아 둔다. 시리얼 로그의 `[mem]` 줄에 단계별 남은 양이 나온다
- 연결이 바뀐 직후 75초 동안은 앞 연결을 살아 있다고 본다. 같은 PC 에서 USB 로 쓰다가 Wi-Fi 로만 바꾸면 그동안 사진이 USB 쪽으로 간다
- 터치·기울기 센서·스피커 모듈이 쓰는 I2C 선이 막히면(어느 기기가 데이터 선을 잡고 멈추면) 1초쯤 뒤 스스로 풀고 다시 연다 (`[i2c]` 로그)
- 마이크 장치는 마이크를 켤 때만 연다 (꺼 둔 동안 내부 RAM 7KB 절약)
- 배터리 % 는 전압으로 짐작한다. USB 에 꽂혀 충전이 끝난 채 20분이 지나면 스스로 보정한다 (전에 쓰던 값과 반씩 섞는다).
  전압은 부하·충전 전류로 흔들려서 `firmware/src/battery_level.cpp` 가 보이는 % 를 다듬는다: 배터리로 쓸 때는 줄기만 하고 (더 높게 짐작되는 일이 5분 이어지면 올림),
  충전 중에는 늘기만 한다 (꽂는 순간 오른 전압을 빼고 셈, 충전 끝 전압에 닿은 뒤로는 2분에 1%, 끝나기 전에는 99% 까지).
  PC 가 잠들면 USB 신호가 몇 분씩 끊긴 것처럼 보이는데, 45초 안에 도우미가 보낸 것이 있으면 USB 전원이 들어오는 것으로 본다 (그 사이 전압이 갑자기 떨어졌으면 뽑은 것)
- 화면 글꼴(`firmware/src/fonts/`)은 나눔고딕(NanumGothic Regular, SIL OFL)을 `lv_font_conv` 로 변환해 만들었다. `font_ko_14.c`, `font_ko_20.c`, `font_ko_28.c` 에는 자주 쓰는 한글 2,350자와 영문/숫자가 있고 (`font_ko_28.c` 는 화면에 쓰는 글자만, 나중에 더한 글자는 `font_ko_28_more.c`),
  `font_ko_14.c`·`font_ko_20.c` 에 없는 글자는 `font_sym_14.c`·`font_sym_20.c` 에서 찾는다: 기호(× ÷ − → ≤ ° ℃ ① 등), 그리스 문자, 한글 자모(ㅋ ㅠ), 전각 문자. 기호는 네이버 배포판 나눔고딕(Ubuntu `fonts-nanum` 패키지의 NanumGothic)에서 뽑았다
